# Project progress

## Phase 0 — Scope, environment, and contracts

- Added Python packaging, a development dependency lock, and Git ignore rules.
- Added validated local defaults in `config/dev.yaml` and shared gateway and
  worker payload schemas under `src/waste_assistant/shared/`.
- Added a deterministic test-only predictor and tests for configuration and
  synthetic score isolation.
- Documented setup, proposed resource limits, the one-process gateway
  constraint, and the first real-model milestone in the README.

Development host was Windows x64 with an Intel Core Ultra 7 258V, eight
logical processors, and Python 3.12.14. The checks use CPU only. GPU and LAN
capacity remain unverified.

Verified in a fresh virtual environment using the locked dependencies and
the README install commands. Package import and configuration loading worked.
`pip check`, all five pytest cases, and Ruff lint and formatting checks passed.

## Phase 1 — Dataset audit and reproducible splits

- Verified the original TrashNet archive, its SHA-256, and the published
  class counts. Recorded the source, license references, import commands,
  duplicate review, and class distribution in [dataset.md](dataset.md).
- Added the offline CLI, dataset configuration, Pillow pin, and an integration
  test for corrupt images, conflicting labels, transitive duplicate grouping,
  and repeatable, immutable output.
- Audited 2,527 decodable images. Excluded six files from three exact pairs
  with conflicting labels and kept four reviewed near pairs together.
  The committed snapshot has 1,764 train, 380 validation, and 377 test images.
- Verified that each accepted file matched its checksum and appeared in
  exactly one split. No detected group crossed splits. All six manifest files
  regenerated byte for byte in a separate directory. Dependency, pytest
  (six tests), and Ruff checks passed.

The similarity audit can miss separate views of the same object.

## Phase 2 — Real classifier and offline evaluation

- Trained an ImageNet-initialized MobileNetV3-Small with a new six-class head
  on the frozen TrashNet training split. Selected epoch 7 and a threshold of
  0.6280 using validation only.
- Exported checksum-verified weights, the ordered labels, preprocessing, and
  training metadata. The standalone predictor loaded the saved artifact in a
  fresh process and returned a real prediction.
- Recorded 85.7% accuracy and 0.848 macro-F1 on 377 held-out images. The fixed
  threshold accepted 89.9% of test images at 89.1% accepted accuracy. Two
  fresh evaluation processes produced byte-identical reports.
- Dependency verification, all eight tests, and Ruff lint and format checks
  passed. See the [model instructions and results](model.md) for details.

External real-world classifier evaluation remains open.

## Phase 3 — One inference worker

- Added the FastAPI worker, pinned HTTP dependencies, and the
  [worker setup and API guide](worker.md). The worker loads and warms one
  checksum-verified model at startup and exposes health, readiness, and status.
- Added one admission slot, bounded multipart uploads, and a dedicated
  inference thread. Concurrent inference is rejected, and a timed-out
  computation retains its slot until it finishes.
- Verified the real Phase 2 model over localhost HTTP. Its label, score, and
  model version matched the standalone predictor exactly. An invalid image
  returned 422, and status reported the execution outcomes.
- All 11 tests and Ruff checks passed. Tests covered missing weights, oversized
  uploads, responsive health during inference, and slot retention after timeout.

## Phase 4 — Single-worker gateway and upload demo

- Added the single-worker classification gateway and the Streamlit upload
  form. The gateway bounds uploads, uses the worker's artifact threshold,
  and applies the versioned demonstration ruleset.
- Verified real uploads through the Streamlit form harness and live HTTP
  gateway and worker. Paper returned demo guidance, cardboard prompted
  review, and trash returned unavailable guidance. Invalid image bytes
  returned 422 through the gateway.
- Dependency verification, all 14 tests, and Ruff lint and format checks
  passed. See the [local startup and API guide](demo.md).

Phase 5 starts on request and will add multiple workers, gateway-owned
bounded queues, and baseline scheduling policies.
